# 管理工作区方案

状态：管理工作区首版已实现。已支持个人可见桶清单、详情与文件浏览跳转、建桶草稿预览/保存/回读和本地记录。用户授权与节点容量页显示管理通路未接入状态；集群管理读取及写入接口尚未实现。申请中心默认提供本机申请单填写、保存和复制，沿用团队人工交付流程；无需申请服务器。可选在线审批已实现共享申请、审批、办理状态与人工交付记录，本地端到端测试通过；可选服务的实验室部署与自动管理执行仍待接入。下文描述完整目标。

## 页面与使用路径

保留右侧文件浏览面板；管理员进入可展开的管理工作区。个人连接设置和日常管理分开，避免将桶、用户、节点全部塞入一个设置表单。入口是否可用由后端核验的能力决定，不能由前端的 role 下拉框、用户名或凭据文件存在与否决定。

| 页面 | 主要内容 | 交互方式 |
| --- | --- | --- |
| 总览 | S3 / 管理通路状态、容量、异常节点、未完成变更 | 少量关键指标与待处理事项；显示采样时间和数据来源，未知值不显示为零 |
| 存储桶 | 桶名、负责人、用量、配额、放置目标、交付状态 | 表格筛选；详情抽屉分基本信息、授权、放置、操作记录；新建使用分步表单 |
| 用户与授权 | S3 身份、授权范围、可用操作、密钥状态 | 以用户和桶两个方向查看授权；展示更改前后差异；密钥不进入列表和日志 |
| 节点与容量 | 节点、磁盘标签、实际可用空间、健康、关联桶 | 首期只读；区分物理余量、已用量与配额，不能以卷槽数代替容量 |
| 变更记录 | 操作者、目标、步骤、开始时间、结果、失败阶段 | 可追踪后台任务；刷新后可继续查看；只有明确可重试的步骤才提供重试 |

管理员连接设置放在工作区的设置入口：S3 地址、个人 profile、可选的 Admin 管理连接、已核实的 Orca SSH 别名、检查间隔。秘密只由后端受限存储加载；CA 可选，不因未配置 CA 而阻塞使用系统信任库的连接。

## 核心流程：创建并交付一个桶

1. 填写桶名、负责人、用途、预计数据量、配额、共享范围；选择目标节点/磁盘，或明确委托管理员选择。不预填未经批准的配额。
2. 后端核验本人权限、实时容量、同名桶和现有配置；产生具体变更计划，表明会修改的目标与内容。
3. 用户提交执行后，后台任务创建桶、设置精确放置规则、设置配额与负责人，并做回读验证。业务写入权限在验收完成后交付。
4. 完整交付任务在唯一测试前缀内使用小型合成对象验证上传、下载、哈希和物理落点；清理本次测试对象。
5. 成功后显示可用的 S3 路径、实际落点、授权范围和验收结果。失败时保留已完成步骤，明确标记“已建桶、未交付”，不自动删桶或覆盖整份配置。

已有桶修改放置规则不会迁移已有数据。页面必须把“更改后续分配位置”与“迁移已有数据”作为不同操作。S3 入口地址、Owner 和桶名均不能作为落点证明。

## 权限与 Orca 协作

- S3 权限、原生 Admin 登录、SSH 运维授权分别核验并显示状态；已有获授权的原生命令路径不以网页登录为前置条件。
- 目前后端有个人浏览、设置、草稿及共享申请代理路由；共享审批身份由申请服务核验。新增管理路由必须逐项核验服务端权限与操作范围，不能只依赖隐藏按钮或现有 DSH 浏览器会话认证。
- SeaweedFS 支持哪些授权粒度，以部署版本和拒绝路径验证为准。当前 skill 指出原生 Write 包含 DeleteObject，不能把插件“允许上传 / 允许删除”开关描述为全局服务端隔离。
- dsh-osslab 负责管理对象模型、参数校验、变更计划、任务状态和结果呈现；Orca 负责经核实的远端状态读取及原生命令执行。共享同一管理服务供前端和 agent 调用，避免两套执行逻辑。
- 管理动作使用固定命令适配与结构化参数，不向普通成员暴露任意 SSH 命令、Master/Filer 端口或管理员密钥。
- 每项变更保留具体操作范围、授权上下文、配置版本、备份引用和回读结果；执行前重新核验权限和状态，防止过期计划覆盖新配置。审计记录不含密钥、签名 URL 或真实业务对象路径。

## 开发顺序

1. **管理只读基础**：能力核验、管理连接、桶/用户/节点列表、容量来源与时间、错误与未授权状态。
2. **日常管理闭环**：建桶交付、配额、负责人、经过验证的共享授权，以及持久化任务与变更记录。支持前端和 agent 发起相同操作。
3. **高级运维**：密钥轮换、已有桶迁移、服务参数变更等，分别设计依赖检查、业务影响和恢复步骤；不作为首页的一键操作。

设计依据：本机 `oss-lab-admin` skill（2026.09.13.1）。其中节点地址、磁盘标签和服务版本均是历史基线，接入时必须重新核验。
